Tasks carry a priority, a category and an optional due date. A calendar view
shows what's due when, and a stats view tracks completion rhythm across the
week. Runs on **Android, iOS and web** from one codebase.

> [!NOTE]
> **Working prototype.** Authentication, task CRUD, calendar and statistics all
> work. Read [Known limitations](#known-limitations) before deploying it
> anywhere real.

## Features

- **Multiple sign-in methods** — email/password, Google Sign-In, and phone (SMS OTP)
- **Task management** — create, edit, complete and delete tasks with title,
  description, priority (Low/Medium/High) and one of eight categories
- **Due dates and filters** — filter by All, Today, This Week or Completed
- **Calendar view** — month/week calendar with due-date markers, powered by `table_calendar`
- **Statistics** — completion rate, per-category and per-priority breakdowns,
  overdue counts, and a seven-day activity chart
- **Offline support** — Firestore local persistence is enabled, so tasks are
  readable without a connection and sync when it returns
- **Light and dark themes** — Material 3, with the choice persisted to secure storage
- **Account management** — profile editing, password change, and feedback submission

## Getting started

### Prerequisites

- Flutter SDK 3.35 or newer (`flutter --version`)
- A Firebase project with **Authentication** and **Cloud Firestore** enabled
- The [FlutterFire CLI](https://firebase.google.com/docs/flutter/setup): `dart pub global activate flutterfire_cli`

### Setup

1. **Clone and install dependencies**

   ```bash
   git clone https://github.com/<your-username>/cadence.git
   cd cadence
   flutter pub get
   ```

2. **Connect your own Firebase project**

   The committed `firebase_options.dart`, `google-services.json` and
   `GoogleService-Info.plist` point at the original developer's project. Replace
   them with your own:

   ```bash
   flutterfire configure
   ```

   These files contain client-side identifiers, not secrets — Firebase expects
   them to ship inside the app. Access control is enforced by security rules,
   which is why step 3 is not optional.

3. **Deploy the Firestore security rules**

   ```bash
   firebase deploy --only firestore:rules,firestore:indexes
   ```

   [`firestore.rules`](firestore.rules) restricts every task to the user that
   owns it. **Without this step your database is open to any authenticated
   user** — the app's `where('userId', ...)` query is a convenience, not a
   security boundary.

4. **Enable the sign-in methods** you intend to use in the Firebase console
   under *Authentication → Sign-in method*: Email/Password, Google, and Phone.

   For Google Sign-In on Android, add your SHA-1 and SHA-256 fingerprints to
   the Firebase project settings:

   ```bash
   cd android && ./gradlew signingReport
   ```

5. **Run**

   ```bash
   flutter run
   ```

```bash
flutter test
```

## Data model

Tasks live in the top-level `Todo` collection, one document per task, keyed by
a generated UUID.

| Field | Type | Notes |
| --- | --- | --- |
| `title` | `string` | Required, 1–100 characters |
| `description` | `string` | Optional, up to 500 characters |
| `category` | `string` | One of `AppConstants.todoCategories` |
| `priority` | `string` | `low` \| `medium` \| `high` (lowercase) |
| `status` | `string` | `pending` \| `completed` |
| `createdAt` | `timestamp` | Set on creation |
| `dueDate` | `timestamp?` | Null when no due date is set |
| `completedAt` | `timestamp?` | Set when marked complete, cleared when reopened |
| `userId` | `string` | Firebase Auth UID of the owner |

Feedback submissions go to a separate `Feedback` collection, which is
write-only for users — triage happens in the Firebase console.

### Queries and indexes

The task list filters by `userId`, plus `status` for the Completed filter —
both covered by the composite index in
[`firestore.indexes.json`](firestore.indexes.json). The *Today* and *This Week*
filters are applied client-side so that no additional composite index over
`dueDate` is required.

## Known limitations

- **Desktop is not configured.** The repository contains `macos/`, `windows/`
  and `linux/` folders from `flutter create`, but `firebase_options.dart` has no
  entries for them — launching on desktop throws `UnsupportedError` at startup.
  Run `flutterfire configure` and select those platforms to enable them.
- **Push notifications are not implemented.** `AppConstants.enableNotifications`
  is a placeholder flag; no scheduling or FCM integration exists yet.
- **No pagination.** The home list streams every task for the user. This is fine
  for hundreds of tasks and will need `limit()` plus paging beyond that.
- **`applicationId` is still `com.example.todoapp`.** Change it in
  `android/app/build.gradle` before any store submission.
- **Deprecated Flutter APIs.** Roughly 270 analyzer infos remain, mostly
  `withOpacity` and `ColorScheme.background`, deprecated after Flutter 3.18.
  They compile and run correctly today but should be migrated.
- **`flutter_lints` is on v2**, two major versions behind.
- **Test coverage is thin** — unit tests cover the date and auth-error helpers;
  there are no widget or integration tests yet.
